# Internal V4A MA2 multiplication

Design and machine evidence before implementation for #123/#116. Extend the
existing internal MA2 arithmetic owner with canonical two-word multiplication.
Keep native arithmetic and public profile activation unchanged. This component
returns words and numeric events; it does not implement BASIC expression-stack
movement, diagnostics, ON ERROR or RESUME.

## Evidence and ordered arithmetic

Rebuild the [pinned V4A-12 configuration](rsts-v4a-build.md) from the three pinned
media images. The reconstruction reproduced all eight recorded DOS payloads,
including SY.LDA SHA-256
`e1add1ea800307764a97a0eb8964fb3dca88403825c3e9a500d68eac786cd596`.
Use the same SIMH commit `698dc8a1b2135ab03f1da0be9ee44b5f1beeadc6`
and CPU11/05 with64K. No downloaded binaries are included in this repository.

The traced multiplication entry is octal101170; completion is101404 and the
range TRAP0 is101420. Its two partial-product loops at101474 and101440 do
**different work**. For canonical restored 24-bit significands L and R:

1. Split the right significand into `top=floor(R/256)` and
   `low=(R mod256)*256`. Start a32-bit integer accumulator at zero.
2. Process left bits0..15, least significant first. When a bit is set, add
   `top*65536`; include `low` only for bit15. After each bit, shift the
   accumulator right once, discarding its low bit. If the left low word is zero,
   the original routine skips these sixteen iterations; the same accumulator
   remains zero.
3. Process bits16..23 similarly, including both `top*65536` and `low` for
   every set bit. Bit23 is the restored hidden bit. Each addition/shift keeps
   the same carry as the original two-word add/rotate sequence.
4. Set exponent `eLeft+eRight-128`. If the accumulator is below2^31, subtract
   one from the exponent and retain24 bits by shifting right7; otherwise shift
   right8. The next discarded bit rounds magnitude upward, with no sticky-bit
   accumulator. Propagate a rounding carry. Sign is the operand-sign XOR.
5. A normalized exponent below1 or above255, or a rounding carry past255,
   is numeric event48. Canonical zero operands instead produce zero normally.

All intermediate integers are below2^33 and exactly representable in binary64.
Do not replace the partial products with an exact48-bit product followed by one
rounding step. The original omits low partial-product contributions before the
final rounding, so **operand order can change the final bit**. The captured
positive word pairs demonstrate this (decimal unsigned words):

| Left | Right | Completed words |
| ---- | ----- | --------------- |
| `[16565,1266]` | `[16639,65533]` | `[16693,1264]` |
| `[16639,65533]` | `[16565,1266]` | `[16693,1263]` |

The existing independently booted BASIC `MUL_TIE` probe, whose operands are
`(1.+2.^(-23.))*(1.+2.^(-1.))`, reports conversion bytes `[0,2,64,192]`.
The corresponding machine words `[0x40c0,2]` agree. Conversion-string order is
covered separately by [its representation contract](ma2-conversion-strings.md).
No literal-conversion algorithm is inferred from this calibration.

## Range continuation and result location

Run through the unchanged selected monitor TRAP0 handler, as for
[addition/subtraction range continuation](ma2-range-continuation.md). The inline
mask at101422 is100002; it is data skipped by the handler. Multiplication's
range continuation clears both words at the **returned R1**, which is140006
for captured range calls, versus140004 for normal calls. Reading the old left
operand location140004 would retain an unfinished high word and report a false
nonzero result. The standalone status latch must therefore use140020, outside
all operands and results, rather than140010 which this path clears.

Return a frozen numeric event with code48, the first overflow/underflow reason,
and zero `continuationWords`. Retain returned pointers/masks in the research
fixture, not as a runtime stack policy. Error/unwind behavior in an actual BASIC
expression still needs separate evidence before historical profile activation.
The input boundary, left-before-right validation, explicit unsupported outcomes,
malformed-word errors, detached/frozen words and operation-first validation stay
with the existing arithmetic owner. Unknown operation names still throw.

not generated by the TypeScript implementation. Include all sign combinations,
zero and endpoint neighbors, both normalization paths, exact/halfway/rounding
carries, both operand orders, exponent underflow/overflow and deterministic

SY.LDA and the pinned simulator. It must not download media or execute during
